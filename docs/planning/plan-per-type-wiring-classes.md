# Plan: per-type `*Wiring` classes

> **Status:** In Review
>
> Shipped at `cadab36` (main refactor) + `2c366bb` (raw-type warning cleanup surfaced by the refactor). `WiringClassGenerator` at `no.sikt.graphitron.rewrite.generators` emits one `*Wiring` class per GraphQL type to `<outputPackage>.rewrite.wiring`, covering the five planned categories (regular, nested+BatchKeyField, nested-only, Connection, Edge). `TypeFetcherGenerator` lost `wiring()`, `emitWiring`, `buildWiringEntry`, `buildPropertyOrRecordFetcherEntry`, `buildWiringMethod`. `GraphitronWiringClassGenerator` shrank to a pure aggregator that takes `List<String>` of `*Wiring` class names. `GraphQLRewriteGenerator` simplified per the plan's snippet (schema-only `WiringClassGenerator.generate(schema)`; aggregator receives names). All five design decisions (subpackage `rewrite.wiring`, cross-class `ConnectionHelper` refs, lint ratchet added as `GeneratedSourcesLintTest.wiringAggregatorDoesNotInlineTypeWiring`, schema-only entry point with private records, alphabetical ordering) landed as specified.

## Learnings

- The refactor surfaced five pre-existing raw-type warnings in generated code (one new site in `WiringClassGenerator`, four older sites in `LookupValuesJoinEmitter`, `SplitRowsMethodEmitter`, `ConnectionHelperClassGenerator`, `TypeFetcherGenerator`) that the Spec-state plan hadn't anticipated. Fixed in `2c366bb` by threading `ParameterizedTypeName` + `WildcardTypeName` through JavaPoet `$T` substitution and broadening a couple of `@SuppressWarnings` to cover unavoidable raw `new Foo[n]` array creation. Worth noting for future generator-side refactors: compiler-warning sweeps live at the generated-sources seam, not in the generator's own compilation unit.
- Two follow-up items worth their own `[Backlog]` lines landed in the roadmap in `2c366bb`: `PageInfo` wiring design decision and `TypeResolver` wiring for interface / union types. Both are out of scope for this plan but natural extensions of the same pattern.
