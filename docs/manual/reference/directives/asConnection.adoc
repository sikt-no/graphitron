= @asConnection
:description: Wrap a list field as a Relay cursor-paginated connection, synthesizing the Connection / Edge / PageInfo types and keyset-based fetchers.
:!toc:

Marks a list field as a https://relay.dev/graphql/connections.htm[Relay cursor connection]. The schema-transform stage rewrites the field's return type from `[T!]!` to a synthesized `TConnection` carrying `edges`, `nodes`, `pageInfo`, and `totalCount`; the generator emits keyset-based `seek/limit` SQL with `ROW_NUMBER() OVER (PARTITION BY ...)` for batched per-parent pagination. If the field doesn't already declare pagination arguments, forward-pagination args (`first: Int`, `after: String`) are added automatically; backward (`last`/`before`) and dynamic xref:orderBy.adoc[`@orderBy`] arguments coexist when present.

include::../../_generator-internals-note.adoc[]

`@asConnection` works on three field shapes that the rewrite recognises distinctly: root list fields (one paginated query), child lists under a non-root type (per-parent paginated children), and union/interface lists (multi-table polymorphic pagination). A child connection is always fetched in a query of its own, batched across parents through a `DataLoader`, each parent paging its own rows; xref:splitQuery.adoc[`@splitQuery`] is inferred there, and writing it is redundant.

== SDL signature

[source,graphql]
----
directive @asConnection(
    defaultFirstValue: Int = 100
    connectionName:    String
) on FIELD_DEFINITION
----

== Parameters

[cols="1,1,1,3",options="header"]
|===
| Name | Type | Default | Description
| `defaultFirstValue` | `Int` | `100` | Page size used when the client omits `first:`. Not a cap on `first:`; the cap is the build's `<maxAllowedPageSize>`, which also lowers the unwritten default of 100 to it, and a value written here above it fails the build.
| `connectionName` | `String` | `{ParentType}{FieldName}Connection` | *Deprecated.* Override the synthesized connection type's name. Each connection field should own its own type; sharing a Connection across fields conflates distinct semantic contexts (different parents, filters, orders) at the type level. The override remains supported as a transition mechanism for legacy schemas but is permanently discouraged; fields sharing a name must agree on its shape (see <<constraints>>). See xref:../../how-to/connections.adoc[How-to: Cursor-paginated connections].
|===

When the schema declares the connection type explicitly (the `ActorsConnection!` shape above), the rewrite reuses it instead of synthesising a fresh one, and the same holds for a declared Edge, `PageInfo` or facets type. A declared type is checked against what its shape requires, the Relay specification's fields where it states them (`edges` and `pageInfo` on a connection, `node` and `cursor` on an edge, the four `PageInfo` fields) and graphitron's own facets shape where none does; one that falls short fails the build with xref:../defects.adoc#minted-type-declared-short[`MINTED_TYPE_DECLARED_SHORT`] at the field. `nodes` and `totalCount` are optional. Otherwise a Connection type, an Edge type, and `PageInfo` are generated alongside the field, and their names are derived from the field's coordinate: `Query.stores` above gets `QueryStoresConnection` and `QueryStoresConnectionEdge`. The deprecated `connectionName:` argument replaces the Connection name, and the Edge name follows it, so an override of `SharedMoviesConnection` mints `SharedMoviesConnectionEdge`. Both are the names the legacy generator emitted, so an upgraded schema publishes the connection types its clients already hold fragments against.

Federation directives on the field propagate onto the Connection, Edge, `PageInfo` and facet types graphitron generates for it. `@shareable` on any field makes the generated types shareable. `@tag` follows Apollo's contract rule that a type's tags also appear on every field returning it: a generated type carries the tags that every field it was generated for carries. A type generated for one field takes that field's tags. A type shared by several fields (`PageInfo`, a Connection and Edge shared through `connectionName:`, a facet value type) takes only the tags they have in common, so a contract that excludes one of the fields' tags keeps the shared type for the others.

When the fields disagree, the shared type ends up with fewer tags than some of them, and the build reports `shared-type-tags-narrowed`. Contracts built by excluding tags want this outcome; disable the rule under `<lint><disabledRules>`. A contract built by including tags drops a type that carries none of them, so declare the type yourself with the tags it should have. A type you declare is used as written and inherits nothing.

[#constraints]
== Constraints

* Applies to list-typed fields. The runtime cardinality must be a list; single-cardinality `@asConnection` is rejected at classify time.
* The field must have a stable order: the primary key of the table its target type is bound to, an xref:defaultOrder.adoc[`@defaultOrder`] on the field, or a non-null, single-valued xref:orderBy.adoc[`@orderBy`] argument. A nullable `@orderBy` argument a client may leave out does not count; without one of these, keyset pagination has no anchor and the build fails with `LIST_ORDER_UNDETERMINED`.
* A type the field would generate and the schema declares must have the fields its shape requires; see above and xref:../defects.adoc#minted-type-declared-short[`MINTED_TYPE_DECLARED_SHORT`].
* Every field generating a name must generate it the same way. Two fields sharing a `connectionName:` over different element types, or a `connectionName:` naming a type the field also generates in another role (`PageInfo`, or its own Edge), coin one name two ways; graphitron generates none of the contested names and fails the build with xref:../defects.adoc#minted-name-contested[`MINTED_NAME_CONTESTED`] at each such field. The default `<ParentType><FieldName>Connection` shape never does this, parent and field names jointly disambiguating.
* `defaultFirstValue:` is the page size used when the client omits `first:`; it is not a cap. The cap is the xref:../mojo-configuration.adoc[`<maxAllowedPageSize>`] plugin parameter: a `first:` or `last:` above it is served at it, with `hasNextPage` (or `hasPreviousPage`) `true`. See xref:../../how-to/connections.adoc[How-to: Cursor-paginated connections].
* A child connection is always materialized per parent through a `DataLoader` keyed on the parent's PK or FK, each parent paging its own rows. xref:splitQuery.adoc[`@splitQuery`] is inferred there; written beside `@asConnection` on a child list, it is redundant and draws the `SPLIT_QUERY_REDUNDANT` warning.
* On a field returning a union or interface, at least one implementer must be xref:table.adoc[`@table`]-bound: the connection pages each table-bound participant's rows, so one with none (an interface's own `@table` not counting) has nothing to page and is rejected at build time (`FIELD_WITHOUT_FETCHER`).
* Inline `TableField` placement is not allowed under interface-or-union return types unless the surrounding type axis supports the multi-table emitter; the generator rejects mismatched placements at classify time. (See xref:../../../architecture/principles/development-principles.adoc[Graphitron Development Principles] for the "no generator-side invariant goes unchecked at validate time" rule that backs this.)
