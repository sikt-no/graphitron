= @issue
:description: Mark the voucher field of a table-bound type, so this subgraph vouches for its rows to another subgraph.
:!toc:

Marks the *voucher* field of a table-bound type in a federated subgraph that vouches for the rows its own rules let a caller see, so another subgraph can grant access to them through its database's row-level security. Every other field of the type is *absorbed* into the voucher: sealed inside it, signed, and withheld from this subgraph's published schema, which publishes the voucher alone. The accepting subgraph marks its matching field `@accept`.

NOTE: Graphitron captures `@issue` and derives what the subgraph publishes for it, but does not yet generate the fetcher that issues vouchers, so a schema using it is refused with `VOUCHER_ISSUE_NOT_GENERATED` (see xref:../diagnostics-glossary.adoc#voucher-issue-not-generated[the glossary entry]) for now.

== SDL signature

[source,graphql]
----
directive @issue(scope: String!, ttl: String!, claims: String!) on FIELD_DEFINITION
----

[cols="1,1,3"]
|===
| Parameter | Type | Meaning

| `scope`
| `String!`
| What the voucher is for. The accepting subgraph's `@accept(scope:)` must name the same scope.

| `ttl`
| `String!`
| How long a voucher stays valid, as an ISO-8601 duration such as `PT5M`. Every voucher an operation issues expires at the operation's start plus this.

| `claims`
| `String!`
| The absorbed fields that are the voucher's claims, a field set as `@key(fields:)` spells one: whose rows are vouched for. The accepting subgraph's `@accept(claims:)` names the same fields; the remaining absorbed fields are the key of the vouched row.
|===

== Canonical example

[source,graphql]
----
type VgsResultat @table(name: "soknad_vgs_resultat") {
  id: ID! @field(name: "vgs_resultat_id")
  eierId: String! @field(name: "eier_id")
  voucher: String! @issue(scope: "vgs-resultater", ttl: "PT5M", claims: "eierId")
}
----

`id` and `eierId` are absorbed: the voucher carries them, signed, and the subgraph publishes `VgsResultat` with `voucher` alone. Name and type the absorbed fields exactly as the other subgraph's key fields and claims fields; a mismatch shows up as every voucher being rejected there.

== What the subgraph publishes

* Only the voucher field, marked `@inaccessible` so clients never see it. The absorbed fields, and any arguments they declare, are not part of the published schema, though they stay in the schema as written, where the editor shows and checks them.
* `@key(fields: "voucher", resolvable: false)` on the issuing type, naming the field you marked, after any key you wrote. The type is keyed by its voucher and not resolved here, so a router reaches the other subgraph's entity from this one only through the voucher. The link imports `@inaccessible` for you.
* Every absorbed field is withheld whatever else is refused, so a schema whose `@issue` is refused for another reason still never publishes them.

== Constraints

Each refusal below is reported at the `@issue`, or at the absorbed field it is about.

[cols="1,3"]
|===
| Code | Rule

| `VOUCHER_WITHOUT_FEDERATION_LINK`
| The schema has a federation `@link`: a voucher only makes sense where a router plans across subgraphs, and the key it is reached by needs the link.

| `VOUCHER_ISSUE_TWICE`
| A type issues one voucher: one field per type carries `@issue`.

| `VOUCHER_ISSUE_ON_KEYED_TYPE`
| The issuing type carries no authored `@key`, which would let a router reach the other subgraph's entity without the voucher.

| `VOUCHER_ISSUE_ON_NODE`
| The issuing type is no node: a node is keyed by its id, which the voucher would absorb.

| `VOUCHER_ISSUE_ON_ROOT_TYPE`
| No root operation field returns the issuing type: a voucher vouches for rows reached below a parent this subgraph's rules admitted. A mutation payload's field is no root field.

| `VOUCHER_ISSUE_ABSORBS_NOTHING`
| The issuing type has fields besides the voucher.

| `VOUCHER_WITHOUT_SESSION_STATE`
| The build configures `<sessionState>`, whose `SessionState` carries the caller each voucher is bound to.

| `VOUCHER_TTL_INVALID`
| `ttl` is an ISO-8601 duration of hours, minutes and seconds, such as `PT5M`.

| `VOUCHER_CLAIMS_EMPTY`
| `claims` selects at least one field.

| `VOUCHER_CLAIM_NOT_ABSORBED`
| Each claim names an absorbed field: not a name the type does not declare, not the voucher field, not a nested selection.

| `VOUCHER_CLAIM_REPEATED`
| No claim is named twice.

| `VOUCHER_MEMBER_NOT_SCALAR`
| Each absorbed field is a single scalar or enum value, not a list or an object.

| `VOUCHER_MEMBER_COMPUTED`
| No absorbed field carries a directive giving it a value of its own, such as `@nodeId`, `@service`, `@routine`, `@reference`, `@externalField` or `@pivot`: the voucher reads each off the issuing row.

| `VOUCHER_MEMBER_COLUMN_UNRESOLVED`
| Each absorbed field reads a column of the issuing type's table, by its `@field(name:)` or its own name.
|===

Every absorbed field stays withheld whichever of these is reported. A field marked `@issue` or `@accept` is never absorbed.
