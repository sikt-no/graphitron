= Code Generation Triggers

What graphitron generates from a schema follows from what the store states about each place in it.
This page reads those statements off one running example, the store's own rows beside the schema
that wrote them, and says what each kind of statement makes graphitron generate. Every schema block
and every table here is rendered from a fact document, and the build checks each table against a
real capture of that document.

'''

== The chain

[#diagram-chain]
[source,mermaid]
----
flowchart LR
    SDL[GraphQL schema] --> CAP[capture]
    CAT[jOOQ catalog] --> CAP
    CAP --> F[("facts<br/>graphql_ / graphitron_ / sql_")]
    F --> ANC[anchoring]
    ANC --> O[("occurrences<br/>source, path, bind, producer")]
    O --> EMIT[emit]
    EMIT --> OUT[generated units]
----

*Capture* reads the schema, the jOOQ catalog, the configuration and the classpath into the store,
one family of relations per corpus. *Anchoring* is each gatherer's last step: over the captured facts
it states, for every place a field, argument or input field is used, where its values come from, how
it reaches what it needs, what it binds and whether it runs something of its own. *Emit* reads those
statements and writes the generated code.

The modelling rules every relation obeys are in xref:../explanation/fact-model.adoc[The fact model]
and xref:../explanation/modeling-discipline.adoc[Modelling discipline]; each relation's columns and
its full comment are in xref:schema/index.adoc[the generated schema reference].

One transitional note, so nothing here reads as more settled than it is. A classification walk
(`GraphitronSchemaBuilder` and the sealed `GraphitronSchema` model) still runs beside the store and
still feeds parts of generation. This page describes what the store states, which is what the
generator is moving onto, one emitter at a time.

'''

== The occurrence

An *occurrence* is a use of a declared field, argument or input field, at the place it is reached.
Its coordinate spells that place: `Film.title` on the table-bound `Film`, `Film.details.length` for
the field of `FilmDetails`, which has no table of its own and is only reached under `Film.details`,
and `Query.films(filter.title:)` for an input field inside an argument. The element coordinate names
what it is an occurrence of, so a field declared once is an occurrence at every place it is reached.

A chain starts at a field of a root type or of a table-bound type, and grows through each field
whose type has no table of its own: an argument hangs under its field, an input field under its
argument. A field whose type is table-bound ends the chain, and that type's fields start chains of
their own.

include::examples/_code-generation-triggers.adoc[tag=RunningExample-graphitron_occurrence]

Everything below is stated per occurrence, not per declaration. A plain type reached under two
fields is two sets of facts, because what its fields read can differ at each place.

'''

== Source

An occurrence's *source* is what its values come from: rows of one or more tables, `TABLE`, or an
instance of a class, `OBJECT`. `graphitron_occurrence_source` states the kind, and its two subtypes
name the tables or the class.

* A field of a table-bound type reads that type's table.
* A field nested in a plain type reads what its parent reads, so `Film.details.length` reads `film`.
* An argument reads the table of its field's target, and an input field its argument's.
* A field reached under a producer that hands back objects reads what that producer produces: a
  table record is rows of its table, any other class an object.
* A field of a root type has no source. It executes from nothing, so `Query.films` has no row.

include::examples/_code-generation-triggers.adoc[tag=RunningExample-graphitron_occurrence_source_table]

== Path

An occurrence with a table source must reach the type it returns, and an argument the type its field
returns. `graphitron_path_need` states each such need, and `graphitron_path_need_table` the table it starts on and the table it
lands on, and `graphitron_path` says how the need is met: by joins from a table source, `JOIN`, or
by accessor calls on an object, `ACCESSOR`. A path's origin says where it came from.

[cols="1,3"]
|===
| Origin | Meaning

| `WRITTEN`
| The author wrote it, with `@reference` or `@routine` on the element.

| `INHERITED`
| Written on an interface's field, and followed by each implementation's field.

| `INFERRED`
| Nothing was written, and the path rides the one foreign key between the two tables.

| `EMPTY`
| The path ends where it starts: a column on its own table, a plain type nested in its parent's
  table, an argument filtering its own field's table.
|===

include::examples/_code-generation-triggers.adoc[tag=RunningExample-graphitron_path]

A join path's steps are `graphitron_join_path_step`, one per table it moves through, with the
column pairs it joins on in `graphitron_join_path_step_column` and the key it rode in
`graphitron_join_path_step_key` where one was written, or `graphitron_join_path_step_inferred_key`
where the step inferred it.

include::examples/_code-generation-triggers.adoc[tag=RunningExample-graphitron_join_path_step]

A need nothing meets is a defect at the written position. Had `Film.language` written no key, the
two keys `film` has to `language` would leave its need unmet, and the store would state a
`ROUTE_AMBIGUOUS` defect at the field naming both.

A word on vocabulary. One written or inferred route resolved between one table it starts on and one
table it lands on is a _path_. "The walk" names only the classification walk being dissolved; a
`@reference` chain is never called one.

=== Paths on arguments and input fields

Inputs follow the output rules with fewer forms; a filter will extend them. The author-facing
wording is the manual's xref:../../manual/reference/directives/reference.adoc#path-rules[path
rules], and a rule changes in the same commit as its code and that page.

* An input is bound to a table record: the field's target table, or under a `@service` the table of
  the record type of the parameter it fills. An input type is never table-bound itself.
* Without `@reference` an input's path is `EMPTY`: a nested input is the same row, unnested into
  the bound record.
* On an input that filters, a written path is a join in the condition, a correlated `EXISTS`,
  single- or multi-hop by the output rules. On an input that fills a record, `@reference` goes with
  `@nodeId` only, since a jOOQ record does not nest; anywhere else it is a defect.
* `@nodeId(typeName:)` is bound to its node's table, so it always has a path from the bound table
  to it, inferred exactly as between two table-bound output types: one foreign key, either direction,
  one hop; none or several is `NODE_ID_LANDS_ON_TABLE` and the author writes it. Inference never
  spans hops, and a self-referencing key is never inferred on an input. Where the node's table is
  the bound table and nothing is written, there is no path: the id is the record's own key.
* On an input that fills a record, a written path may span several hops only where identity passes
  along composite keys: every column of the record's first-hop key traces through the path's column
  pairs to a column of the node's key, so the decoded id carries the values. A column that does not
  trace through is a defect naming it.

'''

== Bind

What an occurrence takes is its *binding*, `graphitron_occurrence_binding`, one row per occurrence
and place it binds, keyed by the place and stating its kind.

[cols="1,3"]
|===
| Kind | What the occurrence takes

| `COLUMN`
| A column where its path lands: a scalar reads it, an argument or input field narrows by it.

| `TABLE`
| The table an object or list it returns joins to.

| `NODE_ID`
| A node identity, packing or unpacking the key columns of its node's table.

| `VALUE`
| A member's value off its parent's object.

| `PARAMETER`
| A parameter of a call that consumes it, such as a `@service` method's.

| `EXPRESSION`
| A value an `@externalField` method computes in its producer's query.

| `RESULT_EXPRESSION`
| A value computed over what its producer produced.
|===

Each kind has a relation of its own beneath the binding stating what it takes. In the running
example every scalar binds a column, and so does the filter's `title`, which narrows by
`film.title`:

include::examples/_code-generation-triggers.adoc[tag=RunningExample-graphitron_occurrence_binding]

`graphitron_occurrence_column` names the column, and how the name matched it: by the SQL name, or by
the name jOOQ generated for it, which answers only where no SQL name on the table does.

include::examples/_code-generation-triggers.adoc[tag=RunningExample-graphitron_occurrence_column]

The store does not state every binding yet. In the running example `Film.language`, `Film.actors`
and `Film.inventory` have no `TABLE` row, and the arguments a `@routine` consumes have no
`PARAMETER` row; their writers are still being moved onto the occurrence.

'''

== Producer

An occurrence that binds and runs nothing belongs to the query of its *producer*, the nearest
occurrence up its chain that executes something of its own. `graphitron_occurrence_producer` states
each producer, what it runs and where it starts.

* A `ROOT` producer is a field of a root type. It has no source and runs from nothing.
* A `CHILD` producer starts a query of its own from what its parent produced, batched over all its
  parents: a `@splitQuery` field, a table-bound field under a parent that holds an object rather than
  rows, a payload's data field re-read by key after a write, or a child `@service`.

A child the parent's query can join in does not produce: it binds, and its join path continues its
producer's query. In the running example only `Query.films` produces; every field below it, the
language, the actors and the inventory among them, is read by the one query it runs.

`Film.language` is a `CHILD` because it is written `@splitQuery`; `Film.originalLanguage`, joined in,
produces nothing. A connection carries two more, `COUNT` for its `totalCount` and `FACETS` for its
facets, each run only when a client asks for it; `graphitron_producer` states them for the field
today, and the occurrence will once the connection model lands.

What a producer produces is `graphitron_occurrence_producer_result`: its shape, one record, a list
of records, a connection page, an object or a scalar, with the class its values are where one is
named and, for records, the table they are rows of. The occurrences under a producer bind into that
result.

include::examples/_code-generation-triggers.adoc[tag=ProducerKinds-graphitron_occurrence_producer_result]

A producer's subtypes state what it calls. Every call an occurrence makes is a row of
`graphitron_occurrence_call`, the methods it could make rows of `graphitron_occurrence_call_candidate`
and the one it pins a row of `graphitron_occurrence_call_method`, whatever its kind.
`graphitron_occurrence_producer_service` names, for a `SERVICE` producer's instance method, the
constructor its object is made with;
`graphitron_occurrence_producer_routine` a `ROUTINE` producer's database routine;
`graphitron_occurrence_producer_write` a write's table. `graphitron_occurrence_call_parameter` says
what fills each parameter of a call: an argument, which then binds that parameter, as
`Query.filmsByService(ids:)` binds the second parameter of `filmsByService`, or a value graphitron
supplies, such as the jOOQ context. `graphitron_occurrence_producer_key_row` states where a child
producer under an object starts: the key it takes off that object, lifted onto the key's table.

A table record a `@service` or a write returns carries only its primary key. Every table-bound
field under it is a new producer that lifts from that key and re-selects; none is answered by a
same-table rule, a path or inference off the record. A design that asks whether such a field is
"the same row or a join" is asking the wrong relation: the key row and the lift answer it.

A field returning a `@table` type on its parent's own table is refused unless the schema says how
it is reached: a nesting type, with no table of its own, or a `@reference` keyed on the table's
primary key (xref:../../manual/how-to/map-types-to-tables.adoc#parents-own-row[the parent's own
row]). Graphitron never infers the parent's row; an unwritten same-table path rides the
self-referencing key or fails. The fix for a schema that meets the refusal is in the schema.

'''

== What the facts generate

Each producer becomes a data fetcher, and each producer kind decides what that fetcher runs.

[cols="1,3"]
|===
| Producer | What its fetcher runs

| `SELECT`
| One jOOQ query from its start, `ROOT` from the producer's own table and `CHILD` batched over its
  parents' keys through a DataLoader, selecting what every occurrence under it binds.

| `LOOKUP`
| The same query, keyed by the values the caller supplies, returning one result per key in the order
  given.

| `COUNT`, `FACETS`
| A count or a facet aggregation over the same rows and arguments as the connection that carries it.

| `INSERT`, `UPDATE`, `DELETE`
| The write on its table, then a re-read of the written rows by key for whatever the client selected.

| `ROUTINE`
| A call to the database routine, its rows read as the routine's derived table.

| `SERVICE`
| A call to the method, its parameters filled as `graphitron_occurrence_call_parameter` says, and
  the result read as `graphitron_occurrence_producer_result` says.
|===

The occurrences under a producer shape its query rather than add fetchers. A `COLUMN` binding is a
selected column, or under an argument a predicate on it. A join path is a join in the producer's
query, or a nested `multiset` for a list. A `NODE_ID` binding packs or unpacks key columns, and an
`EXPRESSION` binding is its method's value selected in place. A field that neither produces nor needs
a value of its own, a plain type's field reading its parent's row, is served by the default property
fetcher and generates nothing of its own.

== When nothing is generated

A schema that asks for something the store cannot state is refused at the written position, as a
defect in `graphitron_entry_defect` with a code and the place the author wrote. A need no path meets,
a column that is not there: each is a defect beside the facts it judges, and the build reports it
where the author wrote it. The relation and its codes are in xref:schema/index.adoc[the generated
schema reference].

What an author wrote is stated apart from what took effect. `graphitron_claim` holds each claim a
directive makes, a producer such as `@service` or `@mutation`, a binding such as `@field(name:)` or
`@nodeId`, a type's `@table` or `@error`, as written, and decides nothing; the occurrence's producer
and bindings are what took effect. Two claims one element cannot hold together are one
`CLAIMS_CONFLICT` at its declaration, each claim weighed a row of `graphitron_entry_defect_claim`
under it, and `ROUTINE_LOOKUP_DEFERRED` is the one pair `graphitron_claim_inclusion` reports
otherwise.
