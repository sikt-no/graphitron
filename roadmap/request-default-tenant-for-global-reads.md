# Request default tenant: route global reads to a caller-named tenant

## Goal

Under database-per-tenant routing (`<tenantColumn>`), every request passes the generated factory its *request tenant set*, the tenants it may touch, and global tables (tables without the tenant column) are read from the runtime's *default source*, the one `DataSource` it is constructed with beside its per-tenant map. After this item a request can also name a *default tenant*, one member of its set, and graphitron's own reads of global tables in that request then run on that tenant's connection, under that tenant's *session mount* (the consumer's `<sessionState>` method, which graphitron runs on every connection it takes and which can receive the tenant it mounts for), instead of on the default source. A deployment whose global reference data is present in every tenant database, and whose session mount needs a tenant to run at all, can then serve root fields, `@splitQuery` children and `node` / `nodes` / `_entities` lookups over global types under the caller's own identity. Writes to global tables and `@service` calls keep the default source, because graphitron cannot see whether their SQL is safe to move. A request that names no default tenant behaves exactly as today.

A *tenant-scoped* table, used below, carries the configured tenant column and lives once per tenant database; a *global* table does not.

The shape, over the multi-tenant sakila fixture (`graphitron-sakila-example/src/main/resources/graphql/multitenant.graphqls`, `film_id` as the tenant column), where `language` and `store` are global (an excerpt; the fixture's `@reference` paths are omitted):

```graphql
type Query {
  films(filmId: Int! @field(name: "film_id")): [Film!]!   # tenant-routed by its argument
  languages: [Language!]!                                 # global root
}
type Inventory @table(name: "inventory") {
  inventoryId: Int @field(name: "inventory_id")
  store: Store @splitQuery                                # global child of a tenant row
}
```

```java
// today: languages and every store batch read the default source, mounted with Optional.empty()
Graphitron.newOwnedExecutionInput(Set.of(1, 2), claims);
// after: they read tenant 2's database, on the same connection and mount films(filmId: 2) would use
Graphitron.newOwnedExecutionInput(RequestTenants.withDefault(Set.of(1, 2), 2), claims);
```

The consumer this is for is sis, during its Graphitron 10 port. sis runs one database per institution (`<tenantColumn>INSTITUSJONSNR_EIER</tenantColumn>`, a `String` key) on the owned-connection path, with a `<sessionState>` mount that sets up an Oracle RAS session, which needs an institution number. About 65 sis tables carry no tenant column (national code tables such as `LAND`, `SPRAK`, `INSTITUSJON`, `STUDIENIVA`, `FYLKE`), and every institution database exposes the same views over them, so any of the caller's institution databases gives the same answer. Graphitron 9 read them on the user's own institution connection under the user's own session. Today they can only be read from the fixed default source, whose mount receives `Optional.empty()` and so cannot set up a RAS session; sis's default source therefore hands out no connection, which fails closed and fails every such read. Inline joins of global tables inside a tenant statement already run on the tenant connection and are unaffected.

## The rule

A request names a default tenant through the generated `RequestTenants` value its factory takes (see Implementation). In such a request:

- **Graphitron's own global reads follow it.** A field classified as a global read (`Untenanted.GlobalRead` below) acquires the default tenant's connection: root fields over global tables, batched (`@splitQuery`) children over global tables whatever their parent, multi-table polymorphic fields over global participants, the count and facet queries of a connection over a global table (they ride the same connection carrier), and the per-type groups of `node`, `nodes` and `_entities` for a global type. The connection is the request's one entry for that tenant key, so a request that also routes a field to that tenant takes one connection and runs the mount once, with `Optional.of(tenant)`.
- **Writes and service calls keep the default source.** A global field whose statement writes (a DML mutation, a routine write) or calls a `@service` (including `@globalData`, a service returning a global `@table`, and a child service on a global parent) runs on the default source in every request (`Untenanted.DefaultSource` below). A service's SQL is opaque, so graphitron cannot tell whether it touches tables that exist only on the default source, and a write to replicated reference data in one tenant database would make that database disagree with the rest. The producing field's own re-read, the keyed re-query a DML write or a table-bound service return performs at its own coordinate, stays on the same connection as the write, as today. A payload's children are their own fields (see the payload bullet below). `GraphitronContext.getDslContext(env)`, the hand-written-code accessor, also keeps the default source.
- **A route is never overridden.** Every field that names a tenant keeps its route: an argument (`ArgumentBound`), an ancestor's hand-down (`Inherited`), a parent row (`ParentRowBound`), a decoded id at a dispatch surface (`NodeIdBound`, `EntityRepBound`) and `@tenantFanOut` (`FanOut`). None of them reads the default source today, so the default tenant only replaces the fixed default source where nothing names a tenant.
- **Under a tenant-bound parent, a global batched child reads the default tenant, not the parent's.** `films(filmId: 1) { inventories { store { storeId } } }` in a request whose default tenant is 2 reads the inventories from tenant 1 and the stores from tenant 2. The global child's loader batches parents of every tenant into one statement today (its loader name carries no tenant), and keeps doing so; any tenant's database gives the same answer, which is the premise of naming a default tenant at all. A consumer that wants one connection per request in the common case names the tenant the request mostly touches.
- **A payload's re-projections of global tables are global reads.** A child of a non-table payload that re-projects a global `@table` from the records a `@service` or DML write handed back (a `BatchedTableField` on a record source, whose members are `SELECT` and `REENTRY`, never `WRITE` or `SERVICE_CALL`) is its own coordinate, and classifies `Untenanted.GlobalRead` whatever connection its producer ran on. Under a tenant-routed service this is what makes the child resolve in sis at all: a service on the institution's connection returning a payload with a `land: Land` child reads that child from the default source today, which hands sis no connection. Under a default-source producer (a write to a global table, a `@globalData` service) the child reads the default tenant, which is the consequence stated below.
- **The default tenant must be in the request tenant set and hosted.** `RequestTenants.withDefault` refuses a default tenant outside the set with an `IllegalArgumentException` at the call that made the mistake. The instrumentation refuses an operation whose default tenant has no `DataSource` in this runtime before any field runs, as it refuses an operation built without the set: the default tenant is chosen by the consumer, not the client, so there is no hosting probe to hide, and every global read in the request would otherwise fail one by one.
- **Absent, nothing changes.** The existing factory signature stays, and a request built through it (or through `RequestTenants.of(set)`) reads global tables from the default source, mounted with `Optional.empty()`.
- **The choice is the consumer's.** sis passes a deterministic one (the caller's lowest institution number). Graphitron does not pick one from the set, because the tenant key type need not be ordered and the policy belongs to the deployment.

Consequence to document: in a request with a default tenant, a global read sees a global write from the same request only if the tenant database's view of global data reflects the default source's committed state, since the write and the read run on different databases. The place to meet this is the payload of a write to a global table or of a default-source `@service`. What the producing field renders at its own coordinate (its inline columns and its own keyed re-query) runs on the write's connection and sees the write. Every child of the payload that is its own field over a global table, a `@splitQuery` child of a `@table` payload or the re-projection of a non-table payload's records alike, is a global read and reads the default tenant. A mutation field's transaction commits when the field settles, before its children run, so on a tenant database whose view of global data is the default source's committed state the child sees the row; on one replicated asynchronously it may find nothing and answer null for a row the mutation just wrote. A deployment that writes global data through graphitron and replicates it asynchronously should not name a default tenant on requests that write global data. The build can see this shape (a global field on its own coordinate reachable below an `Untenanted.DefaultSource` field); an advisory on it is left out of this item and can be added if a deployment trips on it.

### Settled questions from the Backlog stub

- **Which global tables follow: all of them.** Naming a default tenant is the deployment's statement that its global tables can be read from any tenant database, so every global table a graphitron read reaches follows it. A per-table declaration (global tables that exist only on the default source) is deferred until a deployment needs both kinds in one request; such a deployment names no default tenant meanwhile. When it comes, it is captured input (configuration or SDL) and lands as a fact in the store, which the arm derivation reads to turn the affected fields from `Untenanted.GlobalRead` to `Untenanted.DefaultSource`, the direction R505's scope takes too; nothing here needs to change shape for it.
- **Tenant-index tables (R505).** R505 is Backlog, and no index table exists yet. An index table lives only on the default source by definition, so R505's index reads must acquire the fixed default source (`dslDefault`), never `dslGlobal`. R505's body carries that constraint.
- **`@globalData` services keep the default source.** The directive's reference page says the service runs on the default source, and the reasons above (opaque SQL, possible writes) apply in full. A consumer that needs a read-only global service on its tenant connection needs a new author statement for it, which is a later item.
- **Dispatch surfaces.** `node`, `nodes` and `_entities` groups for a global type run on the default tenant's connection, one statement per alternative as today; nothing partitions, since a global id carries no tenant.
- **Factory surface: one typed request-tenancy value.** The default tenant is not independent of the set (it must be a member), so the two travel as one generated value whose constructor holds that invariant, rather than as a positional `K` beside the set. See Implementation. It keeps the R975 convention that request-level tenancy is a typed factory parameter (a compile error to get the type wrong, never a stringly context lookup), a swap with a payload argument of the same type no longer compiles, and every existing caller keeps compiling.

## Implementation

**Model: `TenantBinding`.** Today's `record Untenanted()` becomes `sealed interface Untenanted extends TenantBinding permits Untenanted.GlobalRead, Untenanted.DefaultSource`, each leaf a singleton record. Both leaves touch only global tables; they differ only in which connection serves them. `GlobalRead`: graphitron's own SQL over global tables, acquired from the request default tenant when one is named, else the default source. `DefaultSource`: the statement writes or calls a service, so it runs on the default source whatever the request names. Switches that do not care which connection serves the field (`handDownOnly`, `loaderNameDeclaration`, `edgeEstablishesContext` / `edgeDivinesTenant`, the every-path fold, the Inherited-below rejection) match `Untenanted` once; only the acquisition sites match the leaves. The interface javadoc gains one sentence on the pair. This is also the home R505's index reads and the deferred per-table fact land in.

**Classification: `TenantBindingIndex.Fold`.** The leaf is decided from the field's operation members, which the fold already reads (`operationMembers.membersOf(coord)`, `hasKind`):

- In `armOf`, where `!needsTenant` returns `Untenanted.INSTANCE` today, return `Untenanted.DefaultSource` when the members include `OperationMember.Kind.WRITE` or `OperationMember.Kind.SERVICE_CALL`, else `Untenanted.GlobalRead`. `REENTRY` is deliberately not in the test: on a producing coordinate it rides beside the `WRITE` or `SERVICE_CALL` that already decides the leaf, and on a record-sourced child it marks the payload re-projection the rule classifies a global read.
- `globalDataArmOf` returns `Untenanted.DefaultSource`.
- The node-dispatch arm (`NODE_RESOLVE` with no tenant-scoped node types) returns `Untenanted.GlobalRead`: it is a read.

**Command model: `TenantAcquisition`.** Rename `TenantAcquisition.Untenanted` to `TenantAcquisition.DefaultSource`, with javadoc saying it is the fixed default source. Left as `Untenanted`, the name would mean the fixed default source on this axis while `TenantBinding.Untenanted` covers a leaf that follows the default tenant: opposite meanings on two parallel axes. R682 makes `TenantAcquisition` the target for read acquisitions too, where a global-read arm will be needed beside this one. `RoutineWriteCommands.acquisitionOf` maps `Untenanted.DefaultSource` to it; `Untenanted.GlobalRead` is unreachable at a routine write (a write always classifies `DefaultSource`) and throws the generator-bug `IllegalStateException` in the style of the `FanOut` arm. `TenantAcquisitionFragments` and `TenantAcquisitionFragmentsTest` follow the rename mechanically; the rendered `dslDefault(env)` is unchanged.

**Request tenancy value: `RequestTenants`.** A new generated class in `<outputPackage>.schema`, emitted in `<tenantColumn>` builds only beside `TenantConnections` (by `ConnectionRuntimeClassGenerator`, which already owns the request-tenancy runtime surface): `public record RequestTenants(Set<K> tenants, Optional<K> defaultTenant)` with `K` the boxed tenant key type, so the record is not generic. Its compact constructor copies the set (`Set.copyOf`), requires both components non-null, and throws `IllegalArgumentException("Default tenant '…' is not in the request tenant set.")` when a present default is not a member. Named factories `of(Collection<K> tenants)` and `withDefault(Collection<K> tenants, K defaultTenant)`. Valid Java 17.

**Factory: `GraphitronFacadeGenerator`.** Through `buildExecutionInputFactory`, so the forms cannot drift:

- The existing `newOwnedExecutionInput(Collection<K> tenants, <contextArgs...>)` and the escape-hatch `newExecutionInput(DSLContext, Collection<K> tenants, ...)` keep their signatures and wrap the collection as `RequestTenants.of(tenants)`.
- A new overload `newOwnedExecutionInput(RequestTenants requestTenants, <contextArgs...>)`. It differs from the existing one by the first parameter's type, so the two never collide whatever the payload. The escape hatch gets no such overload: it has no carrier, and nothing on that path reads a default tenant.
- Every form writes the one `RequestTenants` value under the existing `TenantConnections.TENANTS_KEY`, so the instrumentation decodes one value. No second context key.

**Instrumentation: `GraphitronConnectionInstrumentationGenerator`.** `beginExecuteOperation` reads a `RequestTenants` off `TENANTS_KEY` instead of a `Collection` (absent still fails the operation before any fetcher runs). When its default tenant is present and `runtime.tenantKeys()` does not contain it, the operation fails before any fetcher runs with an `IllegalStateException` naming the tenant and saying it has no `DataSource` in this runtime. Membership needs no check here; the record's constructor already holds it.

**Generated runtime: `ConnectionRuntimeClassGenerator.tenantConnections`.** The carrier's constructor takes the `RequestTenants` in place of the bare set (multi-tenant builds only) and keeps `tenants` as a field read off it, plus a final `Optional<K> defaultTenant`. A new instance method `dslGlobal()` returns `entryFor(defaultTenant).dsl`, and a static `dslGlobal(env)` sits beside `staticDslDefault` with the same checked-exception wrap. `entryFor` is unchanged: a present key goes through the membership and timed-out checks like any routed key and shares the entry `dslFor(tenant)` uses, which is what gives one connection and one mount per tenant. `dslDefault` is unchanged and keeps meaning the fixed default source. Single-tenant builds emit none of this.

**Emission.**

- `TenantDslEmitter`: `Untenanted.GlobalRead` renders `TenantConnections.dslGlobal(env)` in `resolve` and `dslExpression`; `Untenanted.DefaultSource` renders `TenantConnections.dslDefault(env)` there. `handDownOnly` and `loaderNameDeclaration` match `Untenanted` once. Update the class javadoc's arm list.
- `HandleMethodBody.emitGroupDispatch`: the global-entity branch (`routing != null`, no bound slot) renders `dslGlobal(groupEnv)`.
- `GraphitronContextInterfaceGenerator`: unchanged (`getDslContext(env)` keeps `dslDefault`).
- The `TenantDslEmitter` javadoc's claim that the single-tenant fallback "fails loudly under owned multi-tenant acquisition" is false today (the owned `getDslContext(env)` returns `dslDefault(env)`). Correct the sentence in the same commit, since this item makes the difference between the two acquisitions matter; changing the fallback's behaviour is out of scope.

**Docs.**

- `docs/manual/how-to/tenant-scoping.adoc` §2 gains the paragraph drafted below, after the mount paragraph; the sentence "global tables read the default source" in the routing paragraph gains "unless the request names a default tenant (below)"; the mount paragraph's "the default source, which serves your global tables, receives `Optional.empty()`" is restated so it stays true in both cases.
- `docs/manual/reference/directives/globalData.adoc`: "The service runs on the default source" gains "also in a request that names a default tenant".

**Migration debt.** The `Untenanted` sub-axis refines one arm of the `TenantBinding` axis, a walk-side fold that R682 moves into the store; like R992's arm, it adds no new walk-side registry and captures no new fact. The leaf is a derivation from the field's own reach and operation members, both already inputs the fold reads.

## User documentation (first-client check)

> **Reading global tables from a tenant database.** If your global tables are present in every tenant database (for example as views over shared reference data), a request can name one of its tenants as its *default tenant*, and graphitron then reads global tables for that request from that tenant's database instead of from the default source:
>
> ```java
> ExecutionInput input = Graphitron.newOwnedExecutionInput(
>         RequestTenants.withDefault(permitted, lowestInstitution(permitted)), claims)
>     .query(query).build();
> ```
>
> The default tenant must be in the request's tenant set, or `RequestTenants.withDefault` throws, and it must be one this runtime has a `DataSource` for, or the request fails before any field runs. Global reads then use the same connection, and the same session mount, as any field routed to that tenant, so your mount receives the tenant rather than `Optional.empty()`, and a request that routes to its default tenant anyway takes no extra connection. This covers root fields over global tables, `@splitQuery` fields over global tables (also below a tenant row: they read the default tenant, not the row's), and `node`, `nodes` and `_entities` for global types. Fields that name a tenant are routed exactly as before.
>
> Writes to global tables and `@service` fields, `@globalData` among them, still run on the default source, because graphitron cannot see what their SQL touches. A global read therefore sees a global write made earlier in the same request only if your tenant databases show the default source's committed data. This shows up in the payload of such a write or service: the field's own columns are read with the write and see it, but every field below it that graphitron fetches separately over a global table, whether a `@splitQuery` field or a `@table` field filled from the records your service returned, reads the default tenant's database. The same holds for a payload returned by a service that runs on a tenant, which is what lets its global fields resolve at all. Which tenant to name is your policy; graphitron never picks one. A request built without a default tenant reads global tables from the default source, as before.

  - *Service re-read kept on the write's connection:* a new root `@service` returning `[Language!]!` (a sakila-service method that reads `language` through its `DSLContext`) with default tenant 2 returns the default database's rows and opens no tenant database.

  - *Payload re-projection under a default-source producer:* a new `Query.globalLanguage: GlobalLanguagePayload @globalData @service` (`{ servedBy: String, language: Language }`, the service answering its connection's `current_database()` and a `LanguageRecord` key) with default tenant 2 reports the default database for `servedBy` and returns tenant 2's language row: the consequence the rule states, pinned so a change to it is deliberate.

## Other solutions we've considered

- **Inherit the parent's tenant for a global child under a tenant row** (Graphitron 9's behaviour). It saves a connection when the default tenant differs from the row's, but the global child's loader batches parents of every tenant into one statement, so inheriting would mean partitioning the global loader per tenant (more statements, not fewer) and reading `localContext` at a site whose javadoc promises not to. One rule, "global reads use the default tenant", is cheaper and the consumer controls the common case by choosing it.
- **Decide per emission site, with the model unchanged.** The "writes or calls a service" test would then be evaluated at `resolve`, `dslExpression` and `acquisitionOf` separately; it is one decision and belongs in the model, decided once.
- **A payload's re-projection follows its producer's connection.** It would keep read-your-writes for a default-source producer's payload. But a record-backed payload type can be reached from several producers on different connections, so the classifier would need a new fact (which producers' records reach a type, folded over every path the way the tenant-context fold is) and a rule for types reached from both; and under a tenant-routed producer, sis's common shape, following the producer gains nothing, since any tenant database answers a global read. The read-after-write cost falls only on payloads of default-source producers, which sis cannot serve today anyway (its default source hands out no connection), and is stated as the rule's consequence instead.
- **Move every default-source acquisition, writes and services included.** Smaller diff (only `dslDefault`'s body changes), and it matches Graphitron 9. Rejected because it silently moves opaque service SQL and global writes onto a tenant database the moment a consumer names a default tenant, which contradicts the `@globalData` reference page and has no build-time check.
- **Per-table declaration of replicated global tables now.** No deployment needs a mix in one request; see Settled questions.
- **A default tenant on the runtime constructor.** It cannot vary per caller, and sis's identity is per caller.
- **Graphitron picks the default tenant from the set** (lowest, first). Needs an ordered key type and puts deployment policy in the generator.
- **A positional overload** `newOwnedExecutionInput(Collection<K> tenants, K defaultTenant, payload...)`. Smaller, but it spreads the membership invariant over the factory body, the instrumentation and `entryFor`, writes a second context key, and a swap with a payload argument of the tenant key type compiles (sis's key is a `String`).
- **A builder-style slot** (a generated `Consumer<GraphQLContext.Builder>` helper passed to `.graphQLContext(...)`). It moves the membership check from the call that made the mistake to execution, and is a second request-tenancy idiom beside R975's typed parameter.

Question 1 fails on one seam: the classification rule moves a read the plan says stays on the write's connection, so what the item promises a consumer about payloads is not what the plan builds.

1. **A payload's record-sourced `@table` child is its own coordinate and classifies `Untenanted.GlobalRead` under the rule as written.** The leaf is decided from the field's own operation members (`WRITE` or `SERVICE_CALL` gives `DefaultSource`). A `@service` or DML payload whose child is a global `@table` (a `BatchedTableField` on a record source, the "`@service` / DML payload carriers" arm of `ChildField.sourceShape()`) is a separate DataLoader-backed coordinate whose members are `SELECT` plus the `REENTRY` that `OperationMembers.mintsReentry` adds for a received record; it carries neither `WRITE` nor `SERVICE_CALL`. So in a request with a default tenant, the re-projection of the records the service or write handed back runs on the default tenant's database, not on the default source the producer ran on. That contradicts three statements in the spec: the rule's "the field's own re-read of rows it wrote stays on the same connection as the write" (true only for the site-level re-query on the producing coordinate), the consequence paragraph's "its inline children ... run on the write's connection" with only `@splitQuery` children named as moving, and the first-client doc's "fields fetched together with the write see it, but a `@splitQuery` field over a global table in that payload reads the default tenant's database". This is the ordinary mutation-payload shape, and it is also the shape a `@globalData` service returning records takes, so it is likely the first place sis meets the rule. The Tests section's "service re-read kept" case uses a table-bound root service (one coordinate), which does not exercise it.

   What would satisfy this: decide which connection a record-sourced re-projection below a `DefaultSource` producer uses, and make the rule, the consequence paragraph, the user doc and the tests agree with that choice. Either arm is the author's to pick. One keeps the rule and widens the stated consequence to every child that re-reads the payload's records, not just `@splitQuery` ones, with an execution case over a payload wrapper. The other classifies such a child `DefaultSource`, which needs a fold fact the plan does not have yet (the reentry child does not know its producer), and should say where that fact comes from. In both cases the build-time shape named at the end of the consequence paragraph ("a global batched field reachable below a write or service field") should be restated to cover it.

   *Response:* kept the rule and widened what it says, the first arm. The Rule section gains a bullet classifying a payload's record-sourced re-projection of a global table as `Untenanted.GlobalRead` whatever its producer, with the reason it matters to sis (a tenant-routed service's payload child reads the default source today, which hands sis no connection). The "writes and service calls" bullet now scopes "stays on the write's connection" to the producing coordinate's own re-query. The consequence paragraph names every payload child on its own coordinate, states that a mutation field commits when it settles so the child can see the row, and restates the advisory shape as a global field on its own coordinate below an `Untenanted.DefaultSource` field. The first-client doc says the same. Classification gains the payload child under both producer kinds, Implementation says why `REENTRY` is not in the leaf test, and Tests gain two execution cases, a tenant-routed payload and a `@globalData` payload, the second pinning the consequence. The producer-following arm is recorded under Other solutions, with why it lost.

Verdict: request revisions. Status stays Spec.
