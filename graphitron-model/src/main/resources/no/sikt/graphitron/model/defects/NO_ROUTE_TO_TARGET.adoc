Reported at the element of the path's last step where a path is written, and at the field's declaration where none is, the detail then naming the two tables. Where the path ends on a `@routine`, it is reported at the `@routine`.

A field's rows come from the table its type is bound to, so its path has to arrive there. A written path whose every element was walked can still end on another table. An inferred one joins two tables over the one foreign key between them, and with none, or with both ends one table, there is nothing to infer. From a routine's result the join is on the target's primary-key columns matched by name, so a result lacking one of them has no route either.

*Next step.* Write or correct the path with xref:directives/reference.adoc[`@reference`] so it ends on the field's table. To read the parent's own row, name its primary key or a self-referencing key with `{key:}`, as the detail suggests. For a routine, expose the primary-key columns in its result.
