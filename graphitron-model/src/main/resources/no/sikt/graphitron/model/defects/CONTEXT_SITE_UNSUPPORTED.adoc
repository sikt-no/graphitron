Reported at the `argMapping` entry. Valid: `$context.<key>` binds a parameter to the value the request context carries under the key, which may be spelt apart from the parameter.

Graphitron reads a `$context` entry into the call at a `@service`, root or child. Under `@condition`, `@routine`, `@outbox`, a `@reference` path step's condition and `@record`, the code generated does not read it yet.

*Instead.* On `@service`, write the entry there. Elsewhere name the key in `contextArguments` where the directive takes them, which fills the parameter of the same name, renaming the parameter after the key where the two differ. See xref:directives/service.adoc#constraints[`@service` constraints].
