Each list is read in an order the build states: the one `@defaultOrder` writes, the table's primary key where none is written, or the one a client picks through `@orderBy`. An ordering whose keys cannot be stated would sort by fewer keys than were written, or by none, so the build stops instead. An ordering is refused at the `@defaultOrder`, `@order`, `@orderBy` or `fields` element written, or at the list field; an `index` the table does not have is `ELEMENT_UNRESOLVED`, and a `fields` element's `name` matching no one column of the table is `COLUMN_UNRESOLVED`, the codes every name claimed in vain and every missing column draw.
