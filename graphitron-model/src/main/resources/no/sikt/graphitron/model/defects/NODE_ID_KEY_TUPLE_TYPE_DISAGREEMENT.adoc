Reported at the `@nodeId`, the detail naming the parameter or bean member.

A jOOQ `RecordN` or `RowN` of the key's degree takes a decoded key only where each type argument is the type jOOQ binds the corresponding key column as, in key order, because the tuple is filled position by position from the key.

*Next step.* Type the tuple with the key columns' own types in key order, for example `Record2<Integer, Integer>`, or take the node type's own generated record instead. See xref:directives/nodeId.adoc#named-parameter-decode[Decoding into a producer parameter named for the argument].
