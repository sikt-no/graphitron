Reported at the field's xref:directives/field.adoc[`@field`] where one is written, since that is the name to fix, and at the field otherwise; the detail names the class.

A field below a parent holding a Java object is read off that object by a member of its class. Graphitron reads a record by its components and any other class by its `get` and `is` getters; a bare accessor such as `title()` on a class that is not a record, or a public field, is not one of them. With no member of the field's name, there is nothing to read. A type also reached as a row is judged on its object: the row reading the field as a column does not read it off the object. A jOOQ record, a generated table record of any catalog among them, is read through the Record API rather than by its getters and is not judged here; nor is a class whose supertypes reach one the build does not hand Graphitron, which is `CLASS_SUPERTYPE_NOT_READ`'s.
